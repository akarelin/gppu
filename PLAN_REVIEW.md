## 9. gppu.ld's names
- Decided by Alex: the base class of `gppu.ld`'s table classes is `_Record`, as gppu names its bases (`_Base`, `_PGBase`). `_Record` defines no table and does all the work; a type's class only defines its table. The `Fields` classes are the data models on `_Record`.
- Done: `_Record` holds every record column and the operations `create`, `read`, `update`, `delete`, `list` and `search`, with `find` the select a search's conditions make; `_Event`, `_Activity`, `_View`, `_Link`, and the abstract `_Content`, `_Container` and `_Resource`, are data models on it, and RAN's `_Work` and `_Session` on `_Activity`; every table class is one line on its data model; `tables()` gives a type's class by its code. A request body leaves out the four columns Postgres fills, and sending one is refused. `Stored`, `RecordFields` and the other `Fields` classes, `made()`, `makes()`, `takes()`, `TABLES`, `listed()`, `paged()`, `sort_key()`, `queried()`, `statused()`, `contained()`, `removed()` and `statuses_of()` are gone; `held()` is `clauses()` (gppu 870f694, RAN 1875c2dac). The core's, the files' and the sessions' API documents are unchanged path for path, and RAN `Projects/ld`'s five checks pass, run with `work.py`'s struck `Tie` restored in a copy; `work.py`'s own API document does not build while `Tie` is struck.
- Still written by hand or more than once: `READ`, the core reading a domain's type through one of its own tables; `Fields`, the one body `/records` takes for every type the core makes; the routes, written for `/records`, for `/links` and in `typed()`. `gppu/ld/__init__.py` is 877 lines, where it was 849.
- What that removes: `Stored` and `RecordFields` as two bases; `made()`, `makes()`, `takes()`, `TABLES` and `READ`, four ways from a type to its class; and the create, read, update, search and delete written three times, as `/records`, as `/links` and in `typed()`, and again in part in RAN `Projects/ld` (`work.py`'s parents is `/records/{id}/parents` again). A data model stays under `_Record` only where a type adds columns (`ts`, `span`, `query`, `from_id` and `to_id`, `uid`), and the request body stays a model without the four columns Postgres fills. The routes the controls read (values, tree, linked, graph) stay. `Record` with its table cannot be the base: in SQLModel 0.0.48 a table class derived from one (`Node(Record, table=True)`, also with `__tablename__ = 'node'`) keeps `record` as its table and cannot be selected, also with `concrete`. SQLAlchemy 2.1.4, which SQLModel is built on, maps a child class to its own table with concrete inheritance (`Node(Record)` selects from `node`, and is a `Record`), the child declaring its columns again; its classes are not Pydantic models, so the API's schemas would be classes of their own.
- The specification's own words are Universals (a span's four forms) and Operations (`create`, `read`, `update`, `delete`, `list`, `search`). Its # gppu and # Implementation lines naming `Span`, `Stored`, `listed()` and `paged()` were written from the code, and it says of them "These names are the code's, not approved".
- Not gppu's: `custom_bookmark_type` (sqlakeyset), `CustomizedPage` (fastapi_pagination), `Annotated` (typing).
- One word, two things: `held()`, the clauses of a condition on a key inside `data` or `meta`, and `Held`, a tree row with how many records it holds. `Collection` is three classes: the standard library's `collections.abc.Collection`, which `gppu.fs` itself uses; `gppu.fs.Collection`, the Lake, exported as `gppu.Collection`; and `gppu.ld.Collection`, the Linked Data type that groups the nodes linked to it.
- The Lake is two classes: `gppu.fs.GppuCatalog`, the Locations by uid with `location()` and `location_of()`, and `gppu.fs.Collection`, derived from nothing, which hands every call to it or to a Location's Container and adds writing a Location's configuration back. In the design it came from (`archive/gppu/fs-dumpoftext.py`) a Collection was a Container, a Location was a Container, and `GppuCatalog` was to become the Collection.
- One thing, several implementations: a type code to its class (`tables()` and `READ`); a tree entry (`Held` beside `gppu.tui.TreeEntry`); `Container`, `Record` and `Collection` in both `gppu.fs` and `gppu.ld`, as different classes.
- `statused()`: Alex's States lists the statuses and the moves between them, and his SQL has `status text` unchecked. That a status outside the list is refused and that a type adds its own (work `completed`, `suspended`, `abandoned`; session `completed`) are in the note's Glossary and # Implementation, which are not his. The moves are not enforced.
- The hierarchy is not in the classes. SQLModel's documentation says to inherit only from data models, never from table models, so `Record`, `Node`, `Activity`, `Work`, `Task` and every other table class are siblings, each made of `RecordFields` and `Stored`; the hierarchy is in Postgres's `INHERITS` alone. `made()`, `makes()`, `takes()`, `TABLES`, `READ`, `PARENTS` and the empty `Content`, `Container` and `Resource` rebuild it by hand, and `types_agree()` exists because the types are written twice, in the SQL's `record_types` and in `Type`. `Stored.write()` and `read()`, the create, read and update, are on the table classes and answer HTTP errors, where SQLModel's documentation has them in the routes.
- Every SQL table is written twice: in RAN `Projects/ld/schema.sql`, which makes the store, and as a `gppu.ld` class, whose fields SQLModel reads and writes it by. The classes hard-code each table's columns, the table names that are not the class's name lowercased (`fs_node`, `session_message`, `record_types`), `record_types`' rows (`Type`), the core's tables (`TABLES`) and the table each type is read through (`READ`). Only the types are compared with the store, by `types_agree()` at start; a column that differs shows when a query fails.
- A type is five classes: `Type` (the codes), `TypeCode` (the `type` column read as one), `TypeFields`, `RecordType` (the `record_types` table) and `TypeRead` (what `GET /types` answers). The API gives the types twice: `openapi.json` from `Type`, `GET /types` from `record_types`. `LINKS` carries the link's 0xA0 to 0xAF from the SQL's check apart from `Type`, which, as `record_types`, names 0xA0 alone.
- The participle names (`listed`, `paged`, `queried`, `saved`, `made`, `statused`, `contained`, `held`, `holding`) are one agent's habit; gppu's own code names by verb or noun (`glob_list`, `children`, `save`, `commit`).
